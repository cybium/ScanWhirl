## 2. Pipeline (every design and every code lane)
1. BUILD: DeepSeek lane (exact files, tests first, gate only) or research worker (cited sources).
2. CRITIC: fresh-context DeepSeek, read-only, closed defect list (design: UI_CRITIQUE A-D + research principles;
   code: correctness, data safety, scope, tests, EN+HI, no long dashes, current-docs compliance via context7).
3. JUDGE: GPT-6.1 Sol (`openai/gpt-6.1-sol`, strict reviewer), read-only: PASS / FAIL per item with reasons.
   Use Sol ONLY for judging (ChatGPT allowance is limited; never for long coding).
4. LEAD decides; merges one lane at a time with the cloud gate; device pass on the Infinix (screens captured,
   looked at, EN + HI) before the owner gets an APK.
Integration gate: pushes cancel the running integration run (concurrency). After a MERGE, do not push doc commits
until that run completes (commit locally, push after); verdict via gh run list --branch integration.
Lint: gate.yml now runs lint on every FULL lane gate (ci/<lane>) and on integration; targeted -Tests runs skip it. (11-18: uiicons slipped a WrongConstant error because lane gates never linted.)
Judge rounds: max 2 per lane. After the 2nd FAIL the lead rules on what is left by real user/data impact (must-fix
items get one final rework; pure test-completeness asks without user impact are overruled with a reason), then merges
on a green gate without a 3rd judge round.
Limits (owner 11-18 10:4x): NO fixed lane cap. Gates build/test on GitHub Actions (repo PUBLIC: unlimited
standard-runner minutes, ~20 concurrent jobs); locally a lane is only a remote worker + polling. Real limits: two
running lanes never share a file; a lane that needs another lane's code waits for its merge. Never run gradle locally.
