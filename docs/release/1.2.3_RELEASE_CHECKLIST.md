# ScanWhirl 1.2.3 release checklist (owner, plain English)

Prepared 2026-11-19 from integration 6d861a04 (branch `lane/release123`). Nothing here was signed or
uploaded by an agent; every signing and Play Console step is yours.

- Version: **1.2.3**
- Version code: **26111901** (date code YYMMDDnn; higher than every code used so far: 1.2.2 shipped
  26111602, the newest test copy was 26111803)
- Package: `com.scanwhirl.app` (the Play app; your installed 1.2.2 is replaced by this update)

## 1. Why this release exists

The 1.2.2 build in closed testing **permanently deleted a document when someone tapped "Move to
Trash"**, although the app promised it could be restored for 30 days. That is fixed here, together with
everything else finished since 1.2.2. This is the reason to ship 1.2.3 rather than wait for a bigger
release.

## 2. What changed for a real user

- **Move to Trash keeps the document for 30 days again**, with Undo. This was the data-loss bug.
- **Undo after making a PDF/A copy no longer deletes your original.**
- **Every tool result can also be saved in Documents** (Also save in Documents), so a second copy is
  a choice, not a surprise.
- **One scan can hold 60 pages** and asks "Add more pages?" at the limit.
- **Search shows the page number and a snippet**, and now also finds documents that older builds
  never recognised.
- **Word export reads two-column pages column by column**; if there is no text it says so and offers
  the Text language setting. Excel says to check columns before sorting.
- **PowerPoint pages that were sideways turn upright**, and the slide description is honest
  (a picture slide plus notes).
- **Calmer Home and Tools screens, everyday Hindi, larger-text fixes** (labels no longer break or
  overlap at 200%), the moved-to-Trash Undo bar is reachable above the bottom bar.
- **Vault is safer**: an unfinished Vault is left out of a full backup, and a recovery code is not
  accepted until the Vault setup has really finished.
- **An import you saved, shared or edited is kept**; the app no longer offers to delete it when you
  go Back.

## 3. Build the signed bundle (your PC)

This is the same build you used for 1.2.0, 1.2.1 and 1.2.2 (documented in
`docs/release/LAUNCH_CHECKLIST.md`, section 1).

1. Open a checkout of `lane/release123` at the commit noted at the top of this file, with your
   `keystore/scanwhirl.keystore` and untracked `keystore.properties` in place, as before.
   Never print, copy or commit them.
2. Run, from the repository root:

   ```
   .\gradlew.bat :app:bundleRelease --no-daemon
   ```

3. The signed bundle is written to:

   ```
   app\build\outputs\bundle\release\app-release.aab
   ```

4. If you want to keep it like the earlier releases, copy it to
   `builds\2026-11-19\release-1.2.3\ScanWhirl-1.2.3.aab` and record its fingerprint:

   ```
   Get-FileHash .\ScanWhirl-1.2.3.aab -Algorithm SHA256
   ```

5. **Do not upload the AAB from the GitHub Actions run** (`release-aab` artifact). That one is signed
   with a throwaway CI key for build checking only; Play would reject it.

## 4. Upload and roll out (Play Console)

1. Play Console > **Test and release > Testing > Closed testing** > your track > **Create new release**.
2. Upload `ScanWhirl-1.2.3.aab`. Confirm Play shows version **1.2.3 (26111901)**.
3. Open `docs/release/RELEASE_NOTES_PLAY.txt`. Paste the `<en-US>` block into the English release
   notes, and the `<hi-IN>` block into the Hindi release notes. Do not paste the last line of the file.
   The Hindi block is a draft: have it checked by a native Hindi speaker first (see section 6).
4. Read the pre-launch report afterwards (crashes, ANRs, screenshots).
5. **Save > Review release > Start rollout to Closed testing** at 100%. Review for a closed test is
   usually quick, then testers receive the update.
6. If a tester reports a serious new problem, you can upload a higher build (e.g. 26112001) rather
   than reusing this code number.

## 6. Known limits (not verified on a phone on this exact build)

- **Vault first-time setup and recovery-code change on a real phone** were not re-run on this build;
  the test phone's Vault already existed. The code paths have unit tests and were reviewed, but a
  person should set up a Vault once.
- **A full 60-page scan** (camera pointing down at a desk) was not done end to end on this build.
- **A real Play purchase** (license tester, one-time Pro) was not tapped on this build; the Pro screen
  only shows the price Google Play returns.
- **Hindi**: the new everyday Hindi was checked against a judged glossary and corrected, but not by a
  native speaker. 16 `<!-- review -->` markers are still in the Hindi strings, and the Hindi text in
  these release notes is a draft. Have one native speaker read Home, Tools, the search snippet, the
  export messages and the notes before you trust the Hindi wording.
- **Compress** can still honestly report that it could not reach a very small target; that is the
  intended behaviour, not a failure.
- This build is the same code family as the 1.2.3-test3 QA copy plus later merges, but it is not the
  byte-identical APK that was tested earlier.
